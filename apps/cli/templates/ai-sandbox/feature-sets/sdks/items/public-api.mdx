## Conventions

- Resource IDs are prefixed and opaque: `sbx_`, `snap_`, `vol_`, `key_`.
- Every mutating request accepts `Idempotency-Key`; a replay within 24 h returns the original response.
- Errors share one shape with a stable `code` and a `request_id`.
- Long-running operations (fork, restore) return `202` with the target resources in `provisioning` state; clients poll or subscribe to events.

## Create a sandbox

```bash title="Request"
curl https://api.cloche.example/v1/sandboxes \
  -H "Authorization: Bearer $CLOCHE_API_KEY" \
  -H "Idempotency-Key: 6f1d0c7e-run-4411" \
  -H "Content-Type: application/json" \
  -d '{
        "template": "python-3.12",
        "resources": { "cpu": 2, "memory": "4GiB", "disk": "20GiB" },
        "timeout": "30m",
        "egress": { "policy": "data-analyst" },
        "metadata": { "agent_run": "run-4411", "customer": "c_92" }
      }'
```

## Endpoints in v1

| Method | Path | Purpose |
| --- | --- | --- |
| `POST` | `/v1/sandboxes` | Create |
| `GET` | `/v1/sandboxes/:id` | Inspect |
| `POST` | `/v1/sandboxes/:id/exec` | Run a command, stream with `Accept: text/event-stream` |
| `POST` | `/v1/sandboxes/:id/snapshots` | Snapshot |
| `POST` | `/v1/sandboxes/:id/fork` | Fork, `count` 1 to 16 |
| `POST` | `/v1/snapshots/:id/restore` | Restore into a new sandbox |
| `PUT`, `GET` | `/v1/sandboxes/:id/files/*path` | Upload and download files |
| `DELETE` | `/v1/sandboxes/:id` | Stop and delete |

<Decision title="Versioning">
  Additive changes (new fields, new endpoints, new error codes) ship in v1 at any time. Anything else goes to v2, and v1 is supported for 12 months after v2 ships. We chose path versioning over date-based headers because agent frameworks pin a base URL more reliably than a header.
</Decision>
